# PDF Works: 容量表示と圧縮モードの安全設計（2026-10-20）

## 現在実装済み
- PDFを開く際、読み取り用ワーカープロセスから`file_bytes`を返し、元PDFの実ファイルサイズをヘッダーに表示。
- `core/file_size.py`がB/KiB/MiB/GiBを使い分ける。値は推測ではなく、実ファイルのバイト数。
- **品質維持の独立した最適化モードはbetaへ実装済み（Windows実機未確認）**。既存の別名保存とは異なり、最適化する元PDFを新規ファイルへ書き出して前後差を検証する。標準／容量優先の画像再圧縮は未実装。

## 推奨する段階
1. **品質維持モード**：ページをラスタライズせず、オブジェクト整理・ストリーム圧縮を試す。見た目とテキスト抽出・注釈数・ページ回転を前後比較。効果なし／サイズ増加もあり得る。
2. **標準モード（要検証）**：スキャン画像が主要容量の場合のみ、画像再圧縮を検討。画像/文字混在PDFで検索可能テキストを失わない設計を先行。
3. **容量優先（明確な画質低下あり）**：解像度等の変更をユーザーに明示。プレビューで比較し、「文字がつぶれる」PDFは対象外にする。
4. すべてのモードで保存先指定・元PDF/既存PDFの非上書き・別プロセス保存・実バイト数のBefore/Afterを必須とする。

## 実装前の確認
- 電子署名、フォーム、ページ内リンク、注釈、しおり、パスワード保護、OCRテキスト層への影響。
- スキャンPDFの画像解像度、色、文字の視認性を人工サンプルで計測。
- 単純な再保存で**必ずファイルが小さくなるとは表示しない**。増加時の扱いを事前に決める。
- 40ページと100ページ相当の人工サンプルでメモリ・処理時間・再読込を測定。
- **公開・配布前**にQt/PyMuPDF・日本語フォント・アイコンのライセンスを確認。

未採用：無条件に全ページを画像化して圧縮する方式。本文検索と印刷品質が壊れやすいため、既定機能にはしない。

## 2026-10-20 品質維持モードの実装と安全ゲート

- `core/optimize.py`：Qt GUIとは別のspawn workerから`optimize_lossless`を実行。
- 元PDFのページを画像化せず、`garbage=3`・`deflate=True`・`deflate_images=True`・`deflate_fonts=True`で可逆的なストリーム圧縮を試す。画像をJPEG変換したり、解像度を落としたりしない。
- 保存前後でページ寸法・回転・抽出テキスト・注釈（種類・位置・内容）・リンク（種類・宛先）・しおりを比較。一致しなければ出力を確定しない。人工PDFでは画像レンダリング結果も比較。
- 対応保留：電子署名、AcroForm/対話フォーム、暗号化PDF、添付ファイル付きPDF。再保存の安全を確認できないため事前に拒否する。
- 独立した新規ファイルへ出力。原本・既存ファイルへの上書きは禁止。一時ファイルを再読込・検証後、排他的に確定する。
- **対象は現在開いている元PDF**。編集順・削除・回転の未保存状態は反映しないため、未保存の編集がある場合はボタンを無効化する。編集結果は先に別名保存して開き直す。
- 出力後、実測バイト数のBefore/Afterと削減率または容量増加・変化なしを表示。**小さくなる保証はない**。
- CI：人工1/8/40ページ、テキスト、回転、しおり、注釈、リンク、レンダリング、元PDFハッシュ、既存出力拒否、フォーム/添付ファイル拒否、spawnワーカー保存を検証。
- 未検証：利用者Windows実機での多様な実文書、複雑なフォント/透明/レイヤー、電子署名関連の例外処理、長時間動作。CIに成功しても実運用の保証とはみなさない。
- 次工程：サイズが増加した場合の利用者への扱い、圧縮前後の見た目差の追加試験、標準モードの画像再圧縮試作の採否検討。
