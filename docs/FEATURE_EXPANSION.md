# PDF Works: 追加機能の統合計画
2026-10-20追補。構想と実装を分離。**選択ページ抽出・1ページ単位分割はbetaに実装**。圧縮・文字入れは未実装。指定位置・指定ページ数での分割と元PDF実容量表示をbetaに実装し、CI成功。利用者Windows PCの実機検証は未完了。

## 開発の二本立て
- 正本のデスクトップ製品：Windows PySide6/Qt + PyMuPDF。既存PDFワーカー・非破壊保存を再利用し、WebView2へ戻さない。
- HTML UI Playground：スマートフォンを含むブラウザでSoft Outlineの配置・選択操作を試すための**人工データのみの画面試作**。現在の会話で単一HTML試作品とソースZIPを提供済みだが、**HTML本体はGitHub未保存**。GitHub Pages等のWeb公開も未実施。
- 将来のブラウザ実PDF編集は独立した機能計画として扱う。端末内で処理するかクラウド処理するか、著作権・ファイルプライバシー・ライブラリの利用条件を決めてから採用する。

## 推奨する実装順
**0. 既存betaのWindows実機検証**：Draft PR #1の回転・削除・移動・Undo・別名保存の正常動作を確認。CI成功だけでmainへ統合しない。

**1. 複数選択の共通基盤**：Ctrl/Shiftでの追加・範囲選択、Ctrl+A、矢印、Space、Delete、Undo等の操作をQtページ一覧へ実装。選択集合は元ページID・編集中のページ順序と別管理し、コマンド単位のUndoを実現。タッチHTMLは複数選択モードを使う。[詳細](KEYBOARD_SHORTCUTS.md)。

**2. 共通領域切り出し＋ページ抽出/分割**：既存最優先のROI切り出しと一覧化を維持。選択したページの抽出は「編集後の順序で新規PDFへ保存」。分割は「指定境界・指定ページ範囲・1ページずつ」。名前の衝突、複数ファイル出力時の部分失敗、元ファイル保護を試験する。PyMuPDF処理はQt UIスレッドから分離。

**3. 容量表示と圧縮**：元PDFのバイト数・MiBを読込時に確認。まずオブジェクト整理/ストリーム圧縮の品質維持モード（効果なし／サイズ増加もありうる）。次にスキャン画像向け標準/容量優先モードを選択可能にする。画像劣化、検索テキスト/注釈の保持範囲、解像度変更を明示し、出力後の容量と縮小率を実測。保存は常に新規ファイルへ。

**4. 文字入れ**：本文の直接編集ではなく「テキストオーバーレイ」の非破壊編集から。入力欄、配置、フォント、サイズ、色、Undo、プレビュー、保存を提供。日本語グリフの埋込み・可検索性を試験し、回転/CropBox/異サイズにも対応。学校資料を公開CIに含めない。

## 合格ゲート
- Windows GUIの操作・表示整合・40ページ連続使用、元PDFハッシュ不変、保存後の再読込。
- サンプルPDFは人工生成。個人/学校文書はGitHub・公開HTMLへ送らない。
- 圧縮は**小さくなる保証なし**とする。効果と画質を比較し、原本へ上書きしない。
- Qt/PyMuPDF・日本語フォントの配布ライセンスはEXE公開前に確認。
- 既存のROI切り出し計画を新規機能によって後回しにしすぎない。
