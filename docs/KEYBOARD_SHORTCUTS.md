# PDF Works: Windowsページ操作・ショートカット仕様（設計案）
**2026-10-20 beta実装**：Qtの標準モデル選択動作を用い、Ctrl/ShiftとCtrl+A、一括回転・削除、Undo、Ctrl+O、Ctrl+Shift+Sを接続。[Windows Qt CI #39397018840](https://github.com/moyashimisosoup/pdf-works/actions/runs/39397018840)成功。利用者PCでの実機操作は未確認、Redo等は未実装。

| 操作 | 期待動作 |
|---|---|
| クリック | 単独選択とページ表示 |
| Ctrl+クリック | 選択集合へ追加、既選択なら解除 |
| Shift+クリック | 選択アンカーから指定ページまで連続範囲を選択 |
| Ctrl+Shift+クリック | 既存選択を維持して範囲追加 |
| Ctrl+A | ページ一覧のすべてを選択 |
| ↑/↓、Home/End | フォーカス移動。Ctrlで既存選択維持 |
| Shift+↑/↓ | 選択範囲を伸縮 |
| Space | フォーカスしているページの選択を切替 |
| Delete | 選択ページを確認して削除。全ページ削除は禁止 |
| Ctrl+Z | 編集操作のUndo（選択変更と編集コマンドは区別） |
| Ctrl+Y / Ctrl+Shift+Z | 将来のRedo。未対応時は案内 |
| Ctrl+O | ファイルを開く |
| Ctrl+Shift+S | 名前を付けて保存 |
| Esc | メニュー/ダイアログの取消、適切な文脈では選択解除 |

選択集合、アンカー、現在ページ、キーボードフォーカス、原本ページID、並べ替え後の順序を**別々に保持**。複数削除はインデックスずれを防ぎ、1操作としてUndo。抽出/分割は編集順序を保持し、元PDFに書き戻さない。

テキスト入力欄のCtrl+A・Delete等をページ操作で奪わない。ショートカットはQtのコンテキストとフォーカスに応じて有効化する。HTMLプレビューではブラウザ標準ショートカットを妨げない。

スマートフォンには修飾キーがないため、タップ追加・解除ができる「複数選択モード」を設ける。
## 選択操作の状態と注意点
- Qt `QAbstractItemView.ExtendedSelection` を採用。Qt/WindowsでのCtrlクリック後のShiftクリックは、既存の飛び飛び選択を残しながら範囲が追加されるケースがある。OS標準挙動の実テストを優先し、意図しない選択の強制解除を避ける。
- プログラムから前/次ページへ移動するときは単一選択へ戻すが、一覧上のCtrl/Shift操作では現在表示中のページと選択集合を別扱いにする。
- 回転・削除の一括操作は編集コア`rotate_many/delete_many`に渡し、Undoは一回で戻す。移動は単独選択のみ。全ページ削除は禁止。
- アプリ内PDF表示と異なる入力欄にDeleteのショートカットを横取りしない。
- ギャラリー一覧の上下移動・除外は**PDF本体のページ編集とは別操作**。元画像は不変で、A4一覧PDFの順序/対象だけを変更する。
