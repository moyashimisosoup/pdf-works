# テスト計画：v5
状態：テスト内容の設計。実行済みを意味しない。

## 合格すべき最小機能
| 対象 | ケース | 期待結果 |
| --- | --- | --- |
| 起動 | オフライン、Python導入なしのEXE | GUIが開き、フリーズしない |
| PDF読込 | 1ページ、40ページ、画像主体PDF | ページ数・最初の表示が一致 |
| ページ移動 | 連打・速い移動 | 古いプレビューが後から上書きしない |
| ズーム | 50/100/200/300% | 余白・スクロール・拡大が正しい |
| 回転 | 90/180/任意角度 | 原寸・用紙の扱いが設定通り |
| 編集 | 削除・順序変更・Undo | 残ページと順序が一致 |
| ROI | 座標正規化・ページ方向混在 | 切り出しが画面指定と対応 |
| 切り出し | 全40ページ・一部除外 | 枚数とラベルが一致 |
| 一覧 | リサイズ・スクロール・クリック拡大 | 操作が固まらない |
| 出力 | 編集PDF・一覧PDF・PNG | 再読込で内容・枚数を確認 |
| 上書き | 元PDFと同パス指定 | 拒否し元データは不変 |
| 失敗時 | PDF破損・書込権限なし・容量不足 | エラー表示し編集状態維持 |

## サンプルデータ
- 生成プログラムで人工的な40ページPDFを作成する。
- ページ番号、異なる用紙サイズ、回転、薄い文字、画像主体ページを含む。
- 学校配布資料、個人名入りの手書きサンプル、実際の業務文書をGitHubへ置かない。
- OCR用データは将来、個人情報を除去し承認されたデータだけにする。

## Windows実機
- 1440/1180/950px幅程度と、表示倍率125/150%を含む。
- 内蔵GPU/異なる端末/オフラインなど複数条件。
- 初期基準として40ページを想定するが、性能測定には200ページ以上の人工PDFも使用する。
- 計測ログにはUI操作遅延、CPU/メモリ、ワーカーメッセージ回数、クラッシュ有無を含める。
