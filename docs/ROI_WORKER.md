# ROIのPDFワーカー接続（beta）

2026-10-19時点。対象：`feature/native-page-edit-20261017` のみ。

## 実装した範囲
- `core/crop.py`：表示上の向きに対する正規化ROI (x0,y0,x1,y1) とページ順序をもとにPNGへ切り出し
- `workers/renderer.py`：`roi_export` 要求をspawnワーカー側で処理、QtメインスレッドにPDFレンダリングを持ち込まない
- 元PDFを読み取り専用で利用、既存PNGは上書きしない。処理中エラー時にはこの操作で作られた途中ファイルの削除を試みる
- 36〜300dpi、1出力最大1600万画素。画像はページ単位で順に作成し、40ページを一斉にメモリ保持しない

ワーカー要求例（内部IPC。**UIボタンは未実装**）：

```python
bridge.send(
    "roi_export", generation=current_generation,
    destination_dir="既存の出力フォルダ",
    roi=(0.1, 0.1, 0.45, 0.3),
    pages=edit_session.snapshot(), dpi=200,
)
```

ページIDと追加回転量は`EditSession.snapshot()`から渡す。Qt beta画面の「範囲を選択」を押してドラッグし、「PNG出力」で保存先フォルダを指定できる。開発ブランチのみ、Windows実機操作は未確認。

## GUIの使い方（beta・Windows実機未検証）
1. PDFを開いて「範囲を選択」を押す。
2. PDF表示上で左ドラッグして長方形を作る。青紫の点線が表示される。
3. 「範囲を選択」を解除すると通常のドラッグスクロールへ戻る。指定範囲は保持される。
4. 「PNG出力」を押し、出力先フォルダを選ぶ。同じ相対範囲を現在の編集順すべてのページから200dpiで書き出す。
5. 既存の `roi_*.png` との名前衝突はエラーで止まり、無断上書きを行わない。
6. 「範囲解除」で枠を消す。切り出し結果のギャラリーと一覧PDFは次段階。

## ROIギャラリー（2026-10-19）
- PNG出力成功時に、別のモデルレスQtウィンドウで一覧を開く。出力直後だけでなく「一覧表示」で再表示できる。
- 小・中・大の3サイズ。クリックで右側に拡大プレビュー、ダブルクリックで現在の編集状態に残っている元ページへ移動する。
- Qt `QImageReader` をQRunnableで並列最大3件に抑え、UIスレッドでは縮小画像の`QPixmap`化のみ実施。タイルの保持は最大48件。未読込枠には軽量な書類型プレースホルダーを表示する。
- 画像自体はPNG書出し先フォルダを読み直す。原PDFの生データをギャラリーに渡さず、元PDFの変更は発生しない。
- [Windows Qtギャラリー試験の結果](https://github.com/moyashimisosoup/pdf-works/actions/runs/39239557566) は人工40枚によるGUI試験であり、実PDFの40ページE2Eや利用者PCの操作確認ではない。
